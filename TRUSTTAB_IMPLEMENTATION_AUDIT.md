# TrustTab Implementation Audit

**Audit date:** 2026-11-14  
**Scope:** repository at `D:\trusttab`, compared with requirements supplied in the audit request.  
**Mode:** read-only audit of implementation; this report is the only file created.

## Executive summary

TrustTab has a substantial prototype implementation: a `src/` package, two OpenML dataset loaders, sklearn preprocessing/model pipelines, a multi-seed stress runner, metrics, optional model adapters, calibration helpers, a unified feature-shift benchmark, tracking/reporting utilities, tests, and documentation. The paths for ordinary label-noise and feature-shift runs are connected. That does not make the specified research package release-ready.

The audit found two release blockers that are directly reproducible: `python -m build --no-isolation` rejects the `project.license = "MIT"` metadata under the installed setuptools validator, and the isolated build could not fetch its build requirement because network access is blocked. Also, the package has no CI workflow or documented release/TestPyPI process. The available `.venv` cannot collect the suite because pandas native extension loading is blocked by Windows Application Control, so behavior is not fully verified here.

Research-wise, Adult (OpenML data ID 1590) was the secondary dataset at the original audit point although the blueprint specifies Heart Disease. Later Phase 2 and Phase 3 work restored the intended dataset pair and 200-condition configuration. Phase 4 subsequently integrated an opt-in calibration-rescue path in the unified benchmark with three disjoint partitions and raw/calibrated metrics; see the Phase 4 addendum below. Phase 5 implemented independent Bernoulli training-label flips. Broader provenance fields such as run ID, timestamp, and training duration in raw result rows remain outstanding.

**Verdicts:**

1. **Research implementation readiness:** Not ready for the stated final experiments.
2. **Scientific validity readiness:** Partially sound foundations; not ready to trust final findings, chiefly due to limited repetitions and incomplete statistical plan. Calibration is now implemented but empirical benefit has not been established. The dataset mismatch and noise-protocol deviation noted in the original audit were addressed in later implementation phases.
3. **Python package readiness:** Not ready; configured build currently fails metadata validation and clean-install/import behavior could not be established.
4. **Overall readiness:** **NOT READY — MAJOR IMPLEMENTATION REQUIRED**.

## Research implementation audit

### Datasets and preprocessing

German Credit loader uses OpenML ID 31, checks row and feature counts, maps `good` to 0 and `bad` to 1, and rejects missing values. Adult uses OpenML ID 1590, retains feature NaNs after normalizing question marks and whitespace, and maps `<=50K` to 0 and `>50K` to 1. Both use remote `fetch_openml` and may need network/cache. Tests mock or construct data locally; they do not demonstrate offline loading of a bundled data snapshot. No Heart Disease loader exists, despite that being the intended secondary dataset stated in the prompt. Thus current Adult results cannot substitute silently for the specified second dataset.

Preprocessing is well composed: the factory builds a `Pipeline` containing the `ColumnTransformer`, and runners split before calling `.fit` on training features and noisy training targets. Numeric imputation/scaling and categorical imputation/one-hot encoding are provided; unseen categories are ignored. This supports leakage-safe ordinary preprocessing. Tests do not explicitly prove train/test isolation and there is no calibration-subset flow.

### Noise and experiment protocol

Splits are stratified and deterministic by seed, test labels remain clean, and noisy copies are generated from training targets. The injector now draws an independent Bernoulli(p) mask for training labels, so the binary flip count follows Binomial(n,p) and is not forced to a rounded count. A runner-level test checks that the derived noise seed is forwarded and that the evaluator receives the original clean held-out labels. The blueprint's Part F prose gives the Bernoulli definition, while its pseudocode later specifies `round(p*n)` and fixed-size sampling; the implementation follows the prose definition and the user's explicit Phase 5 approval. The original blueprint should be reconciled to remove that internal inconsistency.

The default research config (`configs/experiments.yaml`) runs German Credit only, three models (LR, RF, XGBoost), five noise levels and five seeds: 75 model/noise/seed fits, not the specified 200. It omits TabPFN and Heart Disease. `final_smoke_test.yaml` explicitly is a smoke test (two models, one dataset, two levels, two seeds); it should not be used as final evidence. Split seed, noise seed, model random state and shift seed are not consistently separate namespaces; the tracking layer helps capture environment/config but raw row data cannot reconstruct all individual stochastic operations.

### Models, metrics, calibration

The model factory provides logistic regression, random forest, XGBoost, and TabPFN, all wrapped in the same preprocessing pipeline. Optional imports give actionable install hints. TabPFN is genuinely reachable from the shared factory/runner, but the research config does not select it and no real fit was verified; the TabPFN dependency has no version constraint. Consequently it is code-integrated but not research-run verified.

`evaluate_classifier` computes accuracy, balanced accuracy, macro-F1, ROC-AUC, Brier, ECE, MCE, adaptive ECE and log loss. Brier is the standard binary mean squared error for the positive-class probability. ECE is the binary top-label convention, comparing accuracy with confidence `max(p, 1-p)` in equal-width confidence bins, not positive-class probability calibration directly. Boundaries use integer bin assignment with confidence 1 clamped into the last bin, and empty bins contribute nothing. The existing test has a zero ECE perfect example but lacks a sufficiently discriminating hand calculation for nonperfect top-label ECE. The benchmark's one-class fallback is duplicated metric logic and omits only undefined ROC-AUC; this is reasonable if the missing value is explicit, but custom evaluator schemas are not enforced.

Sigmoid and isotonic calibration functions are implemented. `calibrate_fitted_classifier` uses `FrozenEstimator` and distinct calibration data correctly in isolation. No experiment runner invokes either helper, splits out calibration data, records raw-vs-calibrated metrics, or creates the required calibration-rescue output. This is a critical gap.

### Statistics and figures

Paired t-tests with mean-difference confidence intervals, Wilcoxon signed-rank tests, and multiple-comparison corrections are implemented. Comparison code matches rows by seed and dataset when available and rejects or drops unmatched pairs. Its interpretation treats seeds as independent pairs; this is reasonable for repeated independent splits, subject to the small `n=5` and dataset-level generalization limitations. Requested Friedman, Nemenyi, effect sizes, and critical-difference diagrams are not implemented. Reports run paired comparisons on provided results, but there is no evidence of final results analyzed under the complete blueprint plan.

The report plots baseline comparisons, label-noise robustness, feature-shift robustness, degradation, and a single selected calibration-related metric. Means and standard deviations over seeds are used in lines/bars. A standalone reliability plot exists. The expected confidence histograms, ranking heatmaps, CD diagrams, explicit multi-dataset comparison figure, and raw-versus-calibrated ECE plot are absent. The report does not create fabricated results; it consumes supplied benchmark rows.

## Packaging and user experience audit

The repository uses a conventional `src/` layout; package initializer files exist throughout. `trusttab.__init__` exports only `__version__`; useful functions are exported through subpackages, so users need internal-looking imports such as `trusttab.experiments`. There is no hardcoded local absolute data path found; dataset loaders accept `data_home`. The README documents editable installation (`pip install -e`) rather than normal end-user `pip install trusttab`, and examples invoke config paths in a repository checkout. Dataset download needs network/cache and optional-model instructions are present.

`pyproject.toml` names the package `trusttab`, version `0.1.0`, uses setuptools, declares Python >=3.11,<3.13, core and optional dependencies, package discovery under `src`, and a `trusttab` console script. The license field currently breaks build validation. There are no project URLs, changelog, CI workflow, release process, TestPyPI plan, or publishing workflow. `requirements.txt` is empty. Since build failed, wheel contents, clean installation, import from outside checkout, console-script installation, and supported dependency resolution remain unverified. TabPFN is not version-pinned; core dependency lower bounds allow untested future combinations.

## Deviations from original blueprint

1. **Adult replaces Heart Disease.** This is a material dataset deviation, not supported as equivalent by the audit evidence. Adult may be a defensible additional benchmark, but it cannot satisfy the requested pair. For TabPFN in particular, feasibility depends on the installed version's supported sample/feature limits and compute; Adult's 48,842 rows may be unsuitable for some TabPFN configurations without a scientifically justified sampling protocol. This must be verified against the selected TabPFN version, not assumed.
2. **The blueprint's noise pseudocode was inconsistent with its formal definition.** Phase 5 corrected the Part F pseudocode to use the approved independent Bernoulli mask; the formal definition and pseudocode now agree.
3. **Feature-shift benchmark and tracking are additional scope.** They are integrated through unified benchmark and reporting paths, but they do not replace the requested calibration rescue or core dataset/model matrix.
4. **Metric set extends the specified set** with adaptive ECE, MCE and log loss; these extras do not appear to invalidate the requested metrics.

## Phase 4 addendum — calibration rescue (2026-11-14)

This addendum supersedes the historical calibration rows and recommendation above. Calibration is an opt-in path in the unified experiment runner. When enabled it uses blueprint proportions (70% train, 15% calibration, 15% test); when disabled, existing train/test behavior is retained. `CalibratedClassifierCV` with `FrozenEstimator` fits sigmoid calibration on calibration predictions and clean labels without refitting the base pipeline. Both raw and calibrated metrics use the same clean test labels and observations. Output retains one row per condition, with raw metrics in the existing columns and calibrated metrics in matching `calibrated_*` columns. Calibration errors are explicit and calibrated metrics are NaN on failure.
